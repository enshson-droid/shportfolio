2019년 나비엠알오 재직 당시에는 나비페이 UI 디자인만 제작했습니다. 이번 포트폴리오에서는 당시 화면을 바탕으로 결제 수단 등록부터 인증과 결제 완료까지의 흐름, 그리고 예외 상황을 현재의 기획 관점에서 다시 정리하고 재설계했습니다.

OUTPUT사용자 플로우 · 화면 구조 · 예외 경로

문제 정의와 기획 목표

사용자의 판단을 줄이는 방향
01 / CONTEXT

결제 맥락 유지

주문 금액과 선택한 결제 수단을 분명히 보여줘 등록 과정에 들어가도 결제 목적을 놓치지 않도록 구성했습니다.

02 / GUIDANCE

다음 행동 안내

계좌 정보, 은행 선택, 1원 인증, ARS 인증을 단계로 나눠 각 화면에 필요한 행동을 하나씩 제시했습니다.

03 / RECOVERY

막힘 없는 복귀

1원이 보이지 않거나 인증 전화를 받지 못했을 때 재요청과 정보 수정 경로를 확인할 수 있게 했습니다.

인증 과정은 상태별로 분리

1원 확인, 전화 요청, 전화 대기, 완료를 서로 다른 화면으로 나눠 사용자가 처리 결과를 알 수 있게 했습니다.

인증 실패 시 다시 시도할 곳 제시

1원 미수신은 재전송, ARS 미응답은 재요청, 잘못된 연락처는 이전 단계 수정으로 복귀하도록 정의했습니다.

등록 뒤 결제로 이어지는 흐름

등록 완료 후 결제 확인 화면으로 돌아가 선택한 수단과 금액을 재확인하도록 연결했습니다.

01 / SERVICE PLAN

서비스 기획서

나비페이의 목적, 이용 상황, 핵심 기능과 설계 범위를 한 장으로 정의했습니다.

기획 방향 · 범위 · 요구사항
서비스 정의

나비엠알오의 주문 과정에서 계좌·카드를 등록하고 인증한 뒤 결제까지 이어주는 간편결제 경험입니다.

주요 사용자

나비엠알오에서 주문을 진행하며 처음 결제 수단을 등록하거나 기존 수단으로 다시 결제하는 구매자입니다.

해결할 문제

수단 등록, 본인 확인, 결제가 길게 이어질 때 사용자가 현재 단계와 다음 행동을 놓치기 쉽습니다.

기획 목표

주문 맥락을 유지하고, 인증 상태를 명확히 알리며, 실패 시 재시도 경로를 제공하는 것입니다.

핵심 기능 범위

주문·금액 확인, 계좌·카드 등록, 은행 선택, 1원·ARS·카드 인증, 결제 확인, 비밀번호 입력, 완료와 수단 관리.

정책 확정이 필요한 항목

실제 금융기관 연동, 인증 제한 횟수와 유효시간, 결제 실패 처리, 환불·취소 정책은 서비스 운영 기준에 맞춰 별도로 확정합니다.
