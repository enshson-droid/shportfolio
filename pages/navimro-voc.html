02 / Problem

기능과 정보가 쌓일수록
완료까지의 길은 길어졌습니다.

B2B 구매자는 상품만 주문하는 것이 아닙니다. 규격을 확인하고, 여러 품목을 담고, 결제 조건을 이해하고, 이후 회계 증빙까지 처리해야 합니다. 각 기능이 존재해도 그 사이의 확인과 되돌아감이 많으면 구매는 끝나지 않습니다.

04 / Insight & Hypothesis

VOC 분석 후 원인 4가지를
기획적으로 분석하여 압축했습니다.

정보를 빼는 대신 우선순위를 정하고, 화면 하나의 개선보다 앞뒤 단계가 이어지는 방식을 바꿨습니다. 아래 가설은 모두 검증 전입니다.

INSIGHT 01

구매 플로우 단축

관찰
상세 → 옵션 선택 → 장바구니에서 같은 결정을 반복 확인합니다.
판단
옵션·수량·금액을 선택 지점과 담기 결과에 연속적으로 노출합니다.
가설
선택 정보를 유지하면 주문까지의 터치 수와 재확인 시간이 줄어들 것입니다.
INSIGHT 02

정보 구조 재정리

관찰
상품 판단에 필요한 규격과 비교 정보가 긴 상세 정보 속에 흩어질 수 있습니다.
판단
구매 결정 정보 → 비교 정보 → 정책·참고 정보로 위계화합니다.
가설
핵심 정보의 위치가 예측 가능하면 옵션 오류와 되돌아가기가 줄어들 것입니다.
INSIGHT 03

B2B 결제·증빙 경험

관찰
결제수단과 증빙 발행 조건, 입금 정보는 구매 후 업무 처리에 직접 영향을 줍니다.
판단
결제 단계에서 조건을 안내하고 주문 후 증빙 상태까지 연결합니다.
가설
발행 시점과 확인 위치를 미리 알면 증빙 관련 문의가 줄어들 것입니다.
INSIGHT 04

탐색·의사결정 지원

관찰
상품명만으로 찾기 어려운 규격 상품은 비교와 추천이 함께 필요합니다.
판단
검색·카테고리·필터·상품평·관련상품을 ‘찾기→고르기’ 흐름으로 연결합니다.
가설
탐색 기준을 일관되게 제공하면 적합 상품 발견률이 높아질 것입니다.
05 / Solution

탐색에서 증빙까지,
구매 과정을 한 흐름으로 설계했습니다.

고객이 상품을 찾고, 규격을 고르고, 결제한 뒤 증빙을 확인하는 각 순간에 필요한 정보와 행동을 이어지도록 설계했습니다.

01

찾기: 검색과 카테고리에서 선택 기준 만들기

홈의 진입점, 검색어와 카테고리, 결과의 필터를 하나의 탐색 과정으로 봅니다.

문제 → 개선상품을 아는 고객과 모르는 고객이 같은 방식으로 탐색하면 규격에 맞는 상품을 고르는 데 시간이 걸립니다.
기획 판단검색어·카테고리·필터·추천 영역을 구분해 출발점에 맞는 경로를 제공합니다.
카테고리 화면 더 보기
02

고르기: 규격과 수량을 결정하는 순간에 집중

상품 상세의 정보 위계를 정리하고, 다중 옵션·장바구니에서도 선택 상태를 잃지 않도록 했습니다.

문제 → 개선긴 상세와 여러 옵션 사이에서 규격·수량·금액을 확인하려고 화면을 오가게 됩니다.
기획 판단핵심 스펙을 앞에 두고 선택 결과를 옵션·담기·장바구니까지 이어서 보여줍니다.
기본 상품 상세 화면 더 보기
03

구매하기: 결제 조건을 이해한 뒤 완료

배송·결제·입금·증빙 조건을 주문 단계에서 읽고, 완료 후에는 다음 행동을 안내합니다.

문제 → 개선증빙과 입금 정보를 주문 후에 찾아야 하면 업무 담당자는 별도 확인과 문의를 하게 됩니다.
기획 판단결제수단별 설명과 최종 금액, 주문 후 입금 안내를 같은 흐름 안에 둡니다.
04

처리하기: 주문과 증빙을 한 맥락에서 확인

구매 완료가 업무 완료는 아닙니다. 주문 상태에서 상세와 서류까지 이어지는 경로를 설계했습니다.

문제 → 개선주문 조회와 증빙 발행 상태가 분리되면 담당자는 어디서 확인해야 할지 다시 찾습니다.
기획 판단마이페이지 진입 → 주문 조회 → 상세 → 증빙 상태의 위치를 고정합니다.
주문 상세 화면 더 보기
06 / Before → After

문제의 위치와 개선의 위치를
일대일로 연결했습니다.

왼쪽은 VOC와 현재 흐름에서 도출한 문제 가설이며, 오른쪽은 이를 다루기 위한 설계 제안입니다. 실제 개선 효과는 아직 측정하지 않았습니다.

구매 단계Before · 문제 가설After · 설계 제안
탐색상품명·규격을 알지 못하면 검색 결과를 반복 탐색검색어·카테고리·필터·추천의 역할을 분리하고 연결
선택상세·옵션·장바구니에서 수량과 규격을 재확인선택 상태와 금액을 단계마다 이어서 표시
결제결제수단별 입금·증빙 조건을 별도 안내에서 확인결제 맥락에서 조건을 설명하고 완료 후 다음 행동 제시
업무 처리주문·배송·증빙 상태의 확인 경로를 다시 탐색마이페이지에서 주문 상세와 서류 상태를 연결

더 확실하게 구매할 수 있도록.

08 / Reflection

기획자로서의 판단

정보를 줄이는 대신,
사용자 플로우에 맞게
다시 놓았습니다.

VOC를 문의 유형 그대로 화면 기능에 대응시키면 ‘증빙 메뉴를 추가하자’처럼 부분 최적화에 머무르기 쉽습니다. 이번에는 고객의 최종 목적을 ‘상품 선택 → 구매 → 업무 처리 완료’로 정의하고, 문의가 발생하는 지점을 구매 흐름의 끊김으로 해석했습니다.

그래서 상세에서는 구매 결정 정보를 먼저, 결제에서는 수단별 조건을 먼저, 주문 후에는 서류 상태를 먼저 보이도록 했습니다. 현재 제안의 강점은 화면 수가 아니라 앞 단계의 선택과 뒤 단계의 확인이 연결된다는 데 있습니다.

이 제안은 과거 VOC와 현재 흐름을 연결해 우선순위를 정한 기획 결과입니다. 다중 옵션 구매와 세금계산서 확인처럼 업무 영향이 큰 구간을 먼저 설계했고, 실제 효과는 서비스 적용 후 지표와 문의 변화를 통해 확인해야 합니다.
